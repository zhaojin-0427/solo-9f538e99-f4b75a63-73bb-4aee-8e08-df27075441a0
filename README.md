# 波段查缺 API（FastAPI + SQLite）

植被指数（如 NDVI）要求**同一景**的红光（red）与近红外（nir）在同一网格像元上
都有效。本服务接收各景各波段的 0/1 有效掩膜，维护每像元的已提交覆盖，并按日期与
网格矩形返回连续缺口，供数据员补报；另提供两期逐像元可算天数对比，供植被
变化分析前筛出覆盖下降的像元。

## 启动

### Docker Compose（推荐）

```bash
docker compose up -d --build
```

- 服务：<http://localhost:8000>
- Swagger 交互文档：<http://localhost:8000/docs>（可直接在页面上提交掩膜与查缺）
- OpenAPI：<http://localhost:8000/openapi.json>
- SQLite 数据持久化在命名卷 `gapcheck-data`（容器内 `/data/gapcheck.db`）

### 本地直接运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 数据库路径可用环境变量覆盖：
# GAPCHECK_DB_PATH=/tmp/gapcheck.db uvicorn app.main:app
```

## API

### `POST /masks` — 提交 / 更正某景某波段掩膜

请求体（JSON）：

| 字段 | 说明 |
| --- | --- |
| `date` | UTC 日期 `YYYY-MM-DD` |
| `scene_id` | 景号 |
| `origin_x` / `origin_y` | 景网格左上角在全局网格中的坐标 |
| `band` | `red`（红光）或 `nir`（近红外），两波段可分别提交、分别更正 |
| `mask` | 行优先二维 0/1 数组，宽、高各不超过 256 格，行长度必须一致；1=有效 |

规则：

- **同景的网格位置与尺寸固定**：首次提交注册几何；之后同景号/同日期再提交若
  原点或宽高不一致，返回 `409`，不写入任何数据。
- 更正只回读**本景**的源掩膜（另一波段），只重算**本景范围**内的覆盖；其他景的
  贡献原样保留。
- 整个提交在一个 SQLite 事务（`BEGIN IMMEDIATE`）内完成，任何失败都回滚，
  已提交结果仍可查询。

### `GET /gaps` — 按日期与矩形查缺

查询参数：`date`、`origin_x`、`origin_y`、`width`、`height`
（矩形宽、高各不超过 256 格）。

判定：任一景的红光与近红外在某格都有效（两景号集合有交集），该格即**齐全**。
其余格子按缺口类别，在每一行内把连续同类格子合并成段返回：

| category | 含义 |
| --- | --- |
| `red_only` | 仅红光有效，缺近红外 |
| `nir_only` | 仅近红外有效，缺红光 |
| `different_scenes` | 两波段都有，但分属不同景，没有同一景的双波段 |
| `both_missing` | 红光与近红外均缺报 |

返回含每类计数、齐全格数与逐行连续缺口段（`y`、`x_start`、`x_end`、`length`）。

### `GET /coverage/compare` — 两期逐像元可算天数对比

做植被变化分析前，找出两期之间“可算覆盖”比例下降的像元。

查询参数：

| 参数 | 说明 |
| --- | --- |
| `origin_x` / `origin_y` | 矩形左上角网格坐标 |
| `width` / `height` | 矩形宽、高（各 1–256 格） |
| `a_start` / `a_end` | 第一期起止 UTC 日期（**含首尾**） |
| `b_start` / `b_end` | 第二期起止 UTC 日期（**含首尾**） |

两期可重叠、可不等长；各自独立计数。规则：

- **某格某天可算**：当天至少有一景在同一格同时提供有效红光与近红外
  （与 `/gaps` 的“齐全”判定一致）。
- 逐格返回两期各有多少**可算天数**（`computable_days_a` / `computable_days_b`，
  行优先二维数组）。
- 用可算天数 / 该期日历天数比较两期比例；B 期比例**严格低于** A 期的格记为
  `decreased_cells`（含两期天数与比例），并按行合并为 `decreased_runs`
  连续段。整数交叉相乘比较，无浮点误差。
- 两期在同一已提交快照中读取。

### `GET /scenes/{date}/{scene_id}` — 回读某景几何与已提交波段信息

## 数据模型与关键保证

SQLite 表（见 `app/db.py`）：

- `scenes`：每景固定几何（日期、景号、原点、宽高）。
- `band_masks`：每景每波段一份源掩膜 BLOB（行优先 0/1），更正按波段覆盖。
- `coverage`：每像元一行（`date,x,y` 主键，`WITHOUT ROWID`），`red_scenes` /
  `nir_scenes` 为提供有效样本的**景号 JSON 数组**。这是更正时无需读取其他景
  掩膜的关键：本景旧贡献从两个数组中移除，再按新掩膜加入即可。`/gaps` 只读它。
- `cell_cumulative`：跨期统计的**稀疏累计检查点**（`x,y,date` 主键）。仅在某格
  某天可算时存一行，`total` 为自记录起点到该日（含）的可算天数。任取日区间
  只需对该格做两次“不晚于端点”的倒序索引探测，与跨度无关。
- `cell_registry`：每格至多一行，记录该格曾有过可算日，使矩形对比读取的统计
  行数严格不超过矩形像元数（不随入库天数增长）。

对应需求的落点：

1. **掩膜和覆盖一起生效，失败仍可查原结果** — 单事务提交，异常即回滚，
   跨期统计也在同一事务内；任何失败时掩膜、覆盖、统计三者一并回滚。
2. **查询取同一已提交状态，无需读取单景掩膜** — `/gaps` 与
   `/coverage/compare` 均只读已提交表，且置于只读事务（单一快照）中；
   WAL 模式下读不阻塞写。对比查询经由 SQLite authorizer 验证**不读**
   `band_masks` 与 `coverage`。
3. **读取的覆盖记录最多和矩形内像元一样多** — 扫描条件为
   `x BETWEEN ... AND y BETWEEN ...`，主键即 `(date,x,y)`，每像元至多一行；
   无覆盖的像元按“两波段都缺”处理，不产生额外记录。
4. **固定矩形对比的取数不随跨度/入库天数增长** — 每格固定 2 次检查点探测；
   每行一条按 `(y,x)` 索引的语句，读取行数 ≤ `width*height`。
5. **更正仅重算本景范围，且只更新翻转格的跨日统计** — 覆盖扫描与回写都限定在
   本景原点与宽高内，只读取本景另一波段的源掩膜；跨日统计仅在本景把某格
   从可算变为不可算（或反向）时更新：插入/删除该日检查点，并对该格**后续**
   检查点整体 ±1（不重算、不回读其他日期覆盖）。
6. **尺寸限制** — 掩膜与查询矩形的宽、高均在 Pydantic / 查询校验中限制为
   1–256。
7. **旧卷兼容** — 启动时若发现旧版本数据卷（有 `coverage`、无统计表），
   从已提交覆盖一次性回填检查点，`stats_meta` 标记保证幂等；已有覆盖不受影响。

```bash

```

齐全、更正只影响本景、几何冲突 409、失败回滚后原结果可查、256 上限、日期隔离；

对比接口校验与 OpenAPI 暴露。

## 目录结构

```
app/
  config.py    # 环境配置与 256 上限
  db.py        # SQLite 连接、建表、旧卷统计回填、事务/快照边界

  services.py  # 掩膜提交更正、覆盖重算、跨期统计维护、查缺与对比
  main.py      # FastAPI 路由（/docs）
tests/         # pytest 端到端用例
Dockerfile
docker-compose.yml
requirements.txt
```
